## Provider Overview

Hermes Agent speaks to **100+ LLM providers**, and every one of them is wired up through the same configuration layer instead of hand-edited files. A single **Nous Portal** subscription covers **300+ frontier agentic models** — Claude, GPT, Gemini, DeepSeek, Qwen, Kimi, GLM, MiniMax, Grok and more — plus the Tool Gateway for web search, image generation, TTS, and a cloud browser.

One hard rule gates everything: Hermes requires a model with **at least 64,000 tokens of context** for agent use with tools. Smaller windows are rejected at startup, and that floor explains a large share of "my provider will not connect" reports.

Two commands do the work, and they are not interchangeable. `hermes model` runs **outside a session** in your terminal and opens the full setup wizard — add providers, run OAuth, paste API keys, register custom endpoints. `/model` is typed **inside an active chat** and switches only between providers and models already configured; it cannot add a provider, run OAuth, or prompt for a key. To add a provider mid-session: exit with `Ctrl+C` or `/quit`, run `hermes model`, then start a new session. See the [provider integration docs](https://hermes-agent.nousresearch.com/docs/integrations/providers).

## Fastest Path: Nous Portal OAuth

On a fresh install, one command covers login, provider selection, and gateway access: `hermes setup --portal` runs the OAuth flow, sets Nous as your provider, and enables the Tool Gateway. On an existing install, run `hermes model` and pick "Nous Portal" from the list instead.

Use `hermes portal info` to inspect your login state and routing. Portal requests carry an auto-aligned `client=hermes-client-v<version>` tag, so the client version travels with each call. Authentication is JWT-based (`inference:invoke`) and automatic, with the opaque session-key path as the fallback when JWT is unavailable.

Install steps are in the [installation guide](https://hermes-agent.nousresearch.com/docs/getting-started/installation), and portal behavior is documented on the [Nous Portal integration page](https://hermes-agent.nousresearch.com/docs/integrations/nous-portal).

## Choosing the Right Setup

Match the setup to the constraint you actually have — convenience, hardware, privacy, or spend — rather than to whichever vendor page you landed on first.

| Setup | Best for | First auth/command | Notes |
| --- | --- | --- | --- |
| OpenRouter (default) | "Just make it work" | `OPENROUTER_API_KEY` in `~/.hermes/.env` | Widest model catalog; routing controls below |
| Nous Portal | One subscription, many frontier models | `hermes setup --portal` | 300+ models plus Tool Gateway; OAuth |
| Manual API keys | Direct vendor accounts and billing | `hermes model` → provider | Per-vendor env vars; mapping table below |
| Claude Max + OAuth | Claude Max subscribers with extra credits | `hermes model` → Anthropic | Requires Max **and** purchased extra usage credits |
| OpenAI Codex via ChatGPT OAuth | ChatGPT plan holders | `hermes model` → OpenAI Codex | Device code by default; `--browser` for loopback PKCE |
| Local Ollama | Mac, no GPU, or maximum privacy | `OLLAMA_CONTEXT_LENGTH=64000 ollama serve` | Ollama's default context usually sits below the 64k floor — raise it |
| vLLM or SGLang | Production GPU serving | `vllm serve ...` | Tool calling requires parser flags |
| OpenRouter routing (or a LiteLLM proxy) | Multi-provider routing | `provider_routing:` block | Sort by price, latency, or throughput |
| Azure AI Foundry | Enterprise compliance | `hermes model` → Azure AI Foundry | OAuth/enterprise path, no plain env var |

## Manual Provider Setup

### API-key providers

Most vendors are an environment variable plus a provider ID. Keys belong in `~/.hermes/.env`, never in `config.yaml`; the authoritative list is the [environment variables reference](https://hermes-agent.nousresearch.com/docs/reference/environment-variables). Typical examples: DeepSeek (`DEEPSEEK_API_KEY`), MiniMax (`MINIMAX_API_KEY`), xAI (`XAI_API_KEY`), Qwen/Alibaba DashScope (`DASHSCOPE_API_KEY`), Tencent TokenHub (`TOKENHUB_API_KEY`), NVIDIA Build (`NVIDIA_API_KEY`), Google/Gemini (`GOOGLE_API_KEY`, with `GEMINI_API_KEY` as an alias), OpenAI direct (`OPENAI_API_KEY`, provider `openai-api`), Fireworks (`FIREWORKS_API_KEY`), Novita (`NOVITA_API_KEY`), and Hugging Face (`HF_TOKEN`). OpenRouter accepts either `OPENROUTER_API_KEY` or the PKCE flow via `hermes auth add openrouter --type oauth`.

### OAuth and enterprise providers

These are configured through `hermes model` because they need a login flow rather than a static key:

- Nous Portal.
- OpenAI Codex — ChatGPT/Codex OAuth, device code by default, or `--browser` / `auth.codex_login_flow: browser` for the loopback PKCE flow on `localhost:1455`.
- GitHub Copilot — device code; token read from `COPILOT_GITHUB_TOKEN`, `GH_TOKEN`, or `gh auth token`.
- Anthropic — Claude Max plus purchased extra usage credits via OAuth, or an API key, or manual setup-token.
- Azure AI Foundry.
- AWS Bedrock — standard boto3 credential chain.
- Google Vertex AI — OAuth2 via service-account JSON or ADC, billed to GCP.

### Subscription plans: what actually works

The documented plan behavior is narrower than the marketing pages suggest. Under Claude Max, only the extra/overage credits are consumed — the base Max allowance is not.

| Plan | Works with Hermes? | Documented requirement |
| --- | --- | --- |
| Claude Max + OAuth | Yes | Requires Claude **Max AND purchased extra usage credits**; only the extra/overage credits are consumed |
| Claude Pro | No | Use `ANTHROPIC_API_KEY` instead ([providers docs](https://hermes-agent.nousresearch.com/docs/integrations/providers)) |
| OpenAI Codex via ChatGPT plan OAuth | Yes | Plan-quota semantics are **not documented** ([providers docs](https://hermes-agent.nousresearch.com/docs/integrations/providers)) |
| xAI SuperGrok / X Premium+ OAuth | Yes | Uses subscription quota; can return HTTP 403 on restricted tiers |
| Google consumer Gemini plan | No | API-key only; Vertex AI bills to GCP ([providers docs](https://hermes-agent.nousresearch.com/docs/integrations/providers)) |

## Switching Models

Choose your model in the `hermes model` wizard (run outside a session); the selection becomes your active model. To set or persist a default, edit `config.yaml`: the `model:` section accepts either `default:` or `model:` as the key, and the two are equivalent.

Custom endpoints use triple syntax — `/model custom:local:qwen-2.5` names provider, endpoint, and model in one token. A bare `/model custom` auto-selects the single loaded model when only one is present on that endpoint.

## Credential Pools

A credential pool holds multiple keys or tokens for the **same** provider. When one key hits a rate limit or a billing quota, Hermes rotates to the next healthy key without stopping the session. The ordering rule matters: **pools are tried first, and a fallback provider fires only after every pool key is exhausted.** Any key already sitting in `.env` is auto-discovered as a one-key pool.

```
hermes auth add openrouter --api-key sk-or-v1-...
hermes auth add openrouter --type oauth
hermes auth add <provider> --type api-key --api-key ...
hermes auth list
hermes auth
hermes auth priority <provider> <target> <n>
hermes auth remove <provider> <index>
hermes auth reset <provider>
hermes auth refresh <provider> [target]
```

`hermes auth list` marks the selected credential with `←` and shows its `id=` and `priority=` fields; bare `hermes auth` opens an interactive wizard. Rotation behavior is set in `config.yaml`:

```yaml
credential_pool_strategies:
  openrouter: round_robin
```

Allowed strategy values are `round_robin`, `least_used`, `fill_first`, and `random`. Credentials are stored in `~/.hermes/auth.json`, and env-borrowed keys appear as `env:` rows that are never persisted.

Two caveats before you build a large pool. Rotating keys resets the provider-side prompt cache, which costs one full-price re-read per rotation on long conversations. For Codex, each `hermes auth add openai-codex` login is its own pool entry, but only **different OpenAI accounts** rotate independently. Full details: [credential pools docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/credential-pools).

## Fallback Chains

Fallbacks handle cross-provider failover, so a rate limit on one vendor does not end the conversation. The canonical shape is a top-level `fallback_providers:` list in `~/.hermes/config.yaml`; the legacy single-pair `fallback_model:` dict is still honored, but `hermes fallback` writes the plural key.

```yaml
fallback_providers:
  - provider: openrouter
    model: anthropic/claude-sonnet-4
  - provider: anthropic
    model: claude-sonnet-4
```

Manage the list interactively with `hermes fallback` and its `add`, `list`/`ls`, `remove`/`rm`, and `clear` subcommands. When a rate-limit response declares a reset time, the primary is benched until then; `fallback.min_switch_reset_seconds: 0` (the default) always switches immediately. The fallback swaps model and provider mid-session without losing the conversation, the chain is tried entry by entry, and activation is one-shot per session — once a fallback engages, it carries that session. See [fallback provider docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/fallback-providers).

## Local Models

### Ollama

Ollama serves on port 11434 and does **not** use its full context by default, which is why local models often fail Hermes's startup check.

| Available VRAM | Default context |
| --- | --- |
| Under 24 GB | 4,096 tokens |
| 24–48 GB | 32,768 tokens |
| 48 GB and up | 256,000 tokens |

The first two tiers (4,096 and 32,768) sit below Hermes's 64k floor; only the 48 GB-and-up default of 256,000 clears it. If your GPU reports one of the lower defaults, raise Ollama's context with `OLLAMA_CONTEXT_LENGTH=64000 ollama serve`, a systemd `Environment=` line, or a Modelfile `PARAMETER num_ctx 64000`. You cannot set context through the OpenAI-compatible API — that is the number one integration confusion for local setups. Confirm the running value with `ollama ps`. More at [ollama.com](https://ollama.com).

### vLLM

```
vllm serve <model> --port 8000 --max-model-len 65536 --tensor-parallel-size 2 --enable-auto-tool-choice --tool-call-parser hermes
```

Tool calling requires both `--enable-auto-tool-choice` and `--tool-call-parser`. Supported parsers include `hermes`, `llama3_json`, `mistral`, `deepseek_v3`, `deepseek_v31`, `xlam`, and `pythonic`. See [vLLM docs](https://docs.vllm.ai).

### SGLang

```
python -m sglang.launch_server --port 30000 --context-length 65536 --tp 2 --tool-call-parser qwen
```

Available parsers are `qwen`, `llama3`, `llama4`, `deepseekv3`, `mistral`, and `glm`. Note that SGLang defaults to 128 max output tokens, so raise that for longer agent turns.

### llama.cpp

```
--jinja -fa -c 64000 -ngl 99 -m model.gguf --port 8080
```

`--jinja` is required for tool calling, and `-np` slots divide the total context across parallel requests. Project docs: [llama.cpp](https://github.com/ggml-org/llama.cpp).

### LM Studio

Start the server with `lms server start` (port 1234), then load with context: `lms load <model> --context-length 64000`. Hermes exposes `model.lmstudio_load_mode` with `jit` or `explicit` values. See [lmstudio.ai](https://lmstudio.ai).

### WSL2

If your model server runs on the Windows host, `localhost` inside WSL2 resolves to the Linux VM, not to Windows — bridge that network gap before blaming the provider.

## OpenRouter Routing

OpenRouter routing lives in a `provider_routing:` block in `config.yaml` and decides which upstream endpoint serves each request.

```yaml
provider_routing:
  sort: "price"
  data_collection: "deny"
```

`sort` accepts `"price"` (the default), `"throughput"`, or `"latency"`, alongside `only`, `ignore`, `order`, `require_parameters`, and per-model `models:` pins. Quick shortcuts: append `:nitro` for throughput or `:floor` for price. The experimental `openrouter/pareto-code` router auto-picks the cheapest model above a coding bar, tunable via `openrouter.min_coding_score` (0.0–1.0, default `0.65`). Details in the [OpenRouter docs](https://openrouter.ai/docs); for proxy-style multi-provider routing see [LiteLLM](https://docs.litellm.ai).

## Verifying Provider Health

`hermes doctor` verifies configuration, credentials, provider connectivity, model access, local endpoints, cache, and the default model in one pass. For individual values use `hermes config get` and `hermes config set`. After any Hermes update, run `hermes config check` and then `hermes config migrate` so older keys keep working. Remember the storage split: secrets in `~/.hermes/.env`, everything non-secret in `~/.hermes/config.yaml`.

## Recommended Workflow

1. **Context check first.** Confirm your intended model exposes at least 64,000 tokens; smaller windows are rejected at startup.
2. **Pick a default provider.** `hermes setup --portal` on a fresh install, or OpenRouter with `OPENROUTER_API_KEY` in `~/.hermes/.env`.
3. **Set a session default.** Choose it in the `hermes model` picker, then persist it in `config.yaml` via `default:` or `model:`.
4. **Add a fallback.** Write a top-level `fallback_providers:` list with at least two entries.
5. **Add credential pools.** Multiple keys per provider, with a `credential_pool_strategies:` entry.
6. **Verify.** Run `hermes doctor`, then `hermes config check` and `hermes config migrate` after upgrades.

## FAQ

### What is the difference between `hermes model` and `/model`?

`hermes model` runs outside a session and is the full setup wizard: add providers, run OAuth, enter API keys, register custom endpoints. `/model` runs inside an active chat and switches only between providers and models already configured — it cannot add providers, run OAuth, or prompt for keys. To add one, exit with `Ctrl+C` or `/quit`, run `hermes model`, then start a new session.

### Does Nous Portal replace individual API keys?

For most work, yes. One Nous Portal subscription covers **300+ frontier agentic models** plus the Tool Gateway, so you do not need per-vendor keys. Direct API keys remain useful for vendor-specific billing, enterprise endpoints, or models outside the portal catalog.

### Why does my local Ollama model fail at startup?

Because Ollama does not load its full context by default — 4,096 tokens under 24 GB of VRAM, 32,768 between 24 and 48 GB, and 256,000 at 48 GB and up — and the lower two tiers sit below Hermes's 64,000-token floor. Start the server with `OLLAMA_CONTEXT_LENGTH=64000 ollama serve`, set a systemd `Environment=` line, or use a Modelfile `PARAMETER num_ctx 64000`. You cannot raise it through the OpenAI-compatible API.

### How do credential pools interact with fallbacks?

Pools are tried first. A fallback provider fires only after every pool key for the active provider is exhausted, so pools handle same-provider rate limits and billing quotas while fallbacks handle whole-provider outages.

### Can I use Claude Pro or a Google consumer Gemini plan?

No. Claude Pro is not supported for OAuth — use `ANTHROPIC_API_KEY`. Google consumer Gemini plans are API-key only, and Vertex AI bills to GCP. Claude Max with OAuth works when Claude Max AND purchased extra usage credits are present; only the extra/overage credits are consumed.

### How do I keep the setup healthy after upgrades?

Run `hermes doctor` to verify config, credentials, connectivity, model access, local endpoints, cache, and the default model. Then run `hermes config check` followed by `hermes config migrate` so any renamed or newly required keys are updated.

## The Bottom Line

In 2026, the safe Hermes provider setup starts with a hard 64,000-token context check, a default provider reachable from one command, and a fallback chain you can actually verify. If you do one thing after reading this, run `hermes doctor`, confirm every configured model clears 64,000 tokens, and add at least one `fallback_providers:` entry before you depend on the setup.
