Small support inbox owners want ticket triage, FAQ answers, and a way to hand off to a human. Can Hermes do this? Partly, and only **as a pattern you assemble**, not as a product feature. The [Hermes messaging gateway](https://hermes-agent.nousresearch.com/docs/user-guide/messaging) connects to platforms, the [cron feature](https://hermes-agent.nousresearch.com/docs/user-guide/features/cron) schedules jobs, and the [project repository](https://github.com/NousResearch/hermes-agent) shows the MIT-licensed codebase. In the sources reviewed, no built-in helpdesk, ticket database, FAQ engine, or handoff primitive is documented, so triage, FAQ answering, and handoff must be built from gateway, cron, skills, and webhooks.

This guide is based on official Hermes documentation and the project repository; we did not run this setup hands-on.

*Planning estimates (not hands-on measurements):* **Difficulty:** Intermediate DIY (a simple CLI, but you assemble the helpdesk behavior yourself). **Time:** about 1-2 hours for one channel, one skill, one cron job, and one webhook route.

## The Bottom Line

Hermes is a general agent gateway with cron, skills, and webhooks, not a helpdesk. It suits a small inbox if you accept DIY assembly. It is a poor fit if you need a ticket database, SLA timers, queues, assignment, or a built-in escalation button, because none of these are documented in the sources reviewed. The gateway's email adapter handles inbound customer mail and the agent replies in-thread. Cron handles scheduled digests. Webhooks handle external events. Handoff is a human-alert step you design yourself.

## Prerequisites

Install Hermes and create a configured agent. You need an account on your chosen channel. For email, use a **dedicated email account** (the [email docs](https://hermes-agent.nousresearch.com/docs/user-guide/messaging/email) recommend against personal accounts). For Gmail, enable 2FA and create an App Password. Give each agent process its own Hermes home, because [two processes sharing one home](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory) compound each other's memory writes.

The [repository README](https://github.com/NousResearch/hermes-agent) lists supported install platforms (Linux, macOS, WSL2, native Windows, and Android/Termux). RAM and CPU requirements are not established by the sources reviewed.

## Architecture: The Support-Automation Pattern

This text diagram is a PATTERN, assembled from documented components:

```
Customer message (Email / Telegram / ...)
        |
        v
[Platform adapter] --> [Per-chat session store] --> [AIAgent]
        |                                              |
        |                                   classifies / drafts reply
        |                                              |
        +-- reply in-thread (email adapter)
        +-- silence token for internal no-op wakes (see Handoff)

Scheduled path:   [Cron job] --(--skill attach)--> digest --> origin chat / local file / platform target
Event path:       [Webhook route] --(skills, prompt)--> agent run --> deliver target
```

The architecture chain (platform adapters, per-chat session store, AIAgent, webhooks, and a cron scheduler that ticks every 60 seconds) is described in the [messaging guide](https://hermes-agent.nousresearch.com/docs/user-guide/messaging). The [sessions doc](https://hermes-agent.nousresearch.com/docs/user-guide/sessions) covers session continuity.

## Step-by-Step Setup

### Step 1: Gateway Setup

Run the interactive wizard, then install and start the background service:

```bash
hermes gateway setup
hermes gateway install
hermes gateway start
```

Use `hermes gateway stop` or `hermes gateway status` to control it later. The gateway is "a single background process that connects to all your configured platforms, handles sessions, runs cron jobs, and delivers voice messages" ([messaging](https://hermes-agent.nousresearch.com/docs/user-guide/messaging)). For unattended support, the event-loop watchdog exits with code 75 on a loop stall so the service supervisor restarts it ([messaging](https://hermes-agent.nousresearch.com/docs/user-guide/messaging)).

### Step 2: One Channel (Email Is the Documented Intake Path)

Email receives and replies in-thread: "Send an email to the agent's address and it replies in-thread" ([email](https://hermes-agent.nousresearch.com/docs/user-guide/messaging/email)). Run `hermes gateway setup`, select Email, and set variables like these. The values below are placeholders you replace:

```bash
EMAIL_ADDRESS=support@your-domain.example   # dedicated account
EMAIL_PASSWORD=<your-app-password>          # placeholder
EMAIL_IMAP_HOST=imap.gmail.com
EMAIL_SMTP_HOST=smtp.gmail.com
EMAIL_ALLOWED_USERS=<comma-separated sender addresses>
EMAIL_AUTHSERV_ID=mx.google.com             # Gmail example; required unless sender authentication is disabled
EMAIL_POLL_INTERVAL=15
EMAIL_HOME_ADDRESS=<admin address for digests>
```

**Access control matters for a customer inbox.** With `EMAIL_ALLOWED_USERS` set, the docs say only listed senders are processed, so arbitrary customers are ignored unless they are on the list. Decide before launch whether you want an allowlist, a broader setting, or pairing, and document the trade-off. The [email docs](https://hermes-agent.nousresearch.com/docs/user-guide/messaging/email) cover the options.

The Email gateway adapter needs no extra dependencies. The separate bundled Himalaya email skill requires the himalaya CLI ([email](https://hermes-agent.nousresearch.com/docs/user-guide/messaging/email)). [Telegram](https://hermes-agent.nousresearch.com/docs/user-guide/messaging/telegram) is another channel option.

Threads differ by channel. In the platform comparison table, Email and Telegram support threads, while WhatsApp, Signal, and SMS do not ([messaging](https://hermes-agent.nousresearch.com/docs/user-guide/messaging)). Pick a channel that supports the thread model your support queue needs.

### Step 3: A Support Skill (FAQ Answering Pattern)

FAQ answering is a **pattern**: the sources reviewed document no FAQ or knowledge-base engine. Skills are on-demand knowledge documents the agent loads when needed, stored in `~/.hermes/skills/` ([skills](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills)). Each installed skill is available as a slash command, and up to five leading `/skill` tokens can stack. Write a support-FAQ skill covering your top questions. The Skills Hub is named in the repository, and the open skills standard is at agentskills.io. Browse the hub's contents yourself before depending on any named skill.

### Step 4: A Cron Job (Digest Pattern)

Create a recurring job with the documented CLI shape:

```bash
hermes cron create "every 2h" "<your digest prompt>" --skill <your-faq-skill>
```

The example uses a placeholder prompt. The cron docs do not document how a cron job reads an inbox, so triage logic of this kind is something you must design and test yourself. Edit pins with `hermes cron edit <job_id> --pin|--unpin` ([cron](https://hermes-agent.nousresearch.com/docs/user-guide/features/cron)). The cron tool supports one-shot and recurring tasks, pause/resume/edit/trigger/remove, and delivery to the origin chat, local files, or platform targets. Model resolution runs per-job pin, then `cron.model` in config.yaml, then the main agent model. A misconfigured job gets `last_status` = `blocked_config`, one alert, and no LLM call ([cron](https://hermes-agent.nousresearch.com/docs/user-guide/features/cron)).

### Step 5: Webhook Intake (External-Event Trigger Pattern)

Webhooks accept events from external services and trigger agent runs ([webhooks](https://hermes-agent.nousresearch.com/docs/user-guide/messaging/webhooks)). Enable them with `hermes gateway setup`, or set:

```bash
WEBHOOK_ENABLED=true
WEBHOOK_PORT=8644
WEBHOOK_SECRET=<global secret>
```

Verify with `curl http://localhost:8644/health`, which should return `{"status": "ok", "platform": "webhook"}`. Routes accept properties such as `events`, `secret`, `prompt`, `filters`, `script`, `skills`, `toolsets`, and `deliver`. A route's `secret` falls back to the global secret, and `INSECURE_NO_AUTH` is for testing only. Payload fields are untrusted, and the docs warn that ["Authenticated does not mean trusted"](https://hermes-agent.nousresearch.com/docs/user-guide/messaging/webhooks).

## Handoff: What the Silence Token Does and Does Not Do

Human handoff is a **pattern**, and the silence token does not solve it alone. The docs say `[SILENT]` (or `NO_REPLY`) suppresses delivery when the agent's final response is exactly that token. But "on a message from a person, a bare silence token is replaced by a short notice," so the bot still answers a customer. Silence tokens are useful for internal wakes and no-op replies, not for taking a conversation away from the bot ([messaging](https://hermes-agent.nousresearch.com/docs/user-guide/messaging)).

A workable handoff pattern therefore has two parts you build: (a) an alert or transcript delivered to a human target through cron delivery or the webhook `deliver` values ([cron](https://hermes-agent.nousresearch.com/docs/user-guide/features/cron), [webhooks](https://hermes-agent.nousresearch.com/docs/user-guide/messaging/webhooks)); and (b) a human who replies from the usual inbox. No dedicated "escalate to human" or "assign to agent" primitive is documented.

## Limits and Risks

- **Terminal-capable tools with outside senders.** The messaging guide's Platform-Specific Toolsets table lists email, Telegram, Signal, SMS, and other platforms with "Full tools including terminal" ([messaging](https://hermes-agent.nousresearch.com/docs/user-guide/messaging)). Restrict toolsets for any route or channel that customers can reach, and treat every payload as untrusted ([webhooks](https://hermes-agent.nousresearch.com/docs/user-guide/messaging/webhooks)).
- **Memory is small and frozen.** MEMORY.md is capped at 2,200 characters and USER.md at 1,375. Both are injected as a snapshot at session start, and over-limit writes return an error ([memory](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory)).
- **Long-running chats.** Messaging chats are one continuous session that survives restarts. The docs recommend `/new` at natural boundaries ([sessions](https://hermes-agent.nousresearch.com/docs/user-guide/sessions)).
- **Profiles.** Memory is scoped per profile ([profiles](https://hermes-agent.nousresearch.com/docs/user-guide/profiles)).
- **Cron recursion.** Cron-run sessions cannot create more cron jobs by default ([cron](https://hermes-agent.nousresearch.com/docs/user-guide/features/cron)).

**Not established by the sources reviewed:** a ticket data model (priority, status, tags, SLA timers, queues, assignment); FAQ or RAG quality; accuracy, latency, or resolution-rate benchmarks; RAM or CPU requirements; SOC 2, GDPR, HIPAA, or ISO 27001 status; pricing or support terms beyond the MIT license; and the webhook payload schema beyond the route properties above. Consult the [repository](https://github.com/NousResearch/hermes-agent) for current install requirements.

## FAQ

**Does Hermes have a built-in helpdesk or ticket system?** None is documented in the sources reviewed. The support flow is a pattern built from the gateway, cron, skills, and webhooks ([messaging](https://hermes-agent.nousresearch.com/docs/user-guide/messaging)).

**Can it auto-answer FAQs?** Yes, as a skill-based pattern. The agent can load a support-FAQ skill on demand ([skills](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills)). A skill can also be attached to a cron job with `--skill` ([cron](https://hermes-agent.nousresearch.com/docs/user-guide/features/cron)) or to a webhook route with `skills` ([webhooks](https://hermes-agent.nousresearch.com/docs/user-guide/messaging/webhooks)). Whether a skill is guaranteed to load for every inbound email is not established by the sources reviewed.

**How do I stop the bot from replying when a human takes over?** The silence token will not do this for a customer message, because a bare token from a person is replaced by a short notice ([messaging](https://hermes-agent.nousresearch.com/docs/user-guide/messaging)). Handle takeover with your own process and your mail rules.

**What happens if a cron job is misconfigured?** It is marked `blocked_config`, one alert is sent, and no LLM call is made ([cron](https://hermes-agent.nousresearch.com/docs/user-guide/features/cron)).

**Which platforms can it run on?** The [messaging docs](https://hermes-agent.nousresearch.com/docs/user-guide/messaging) list more than 20 platforms, including [Telegram](https://hermes-agent.nousresearch.com/docs/user-guide/messaging/telegram). Feature support varies by platform.

**Is it production-ready for support?** The docs describe a watchdog that restarts a stalled gateway and fail-safe cron behavior ([messaging](https://hermes-agent.nousresearch.com/docs/user-guide/messaging), [cron](https://hermes-agent.nousresearch.com/docs/user-guide/features/cron)). They document no SLA or security certification, so validate the setup yourself before relying on it.

## Comparison: Assembled Pattern vs. Dedicated Helpdesk Tool

| Capability | Hermes (assembled pattern) | Dedicated helpdesk tool (typical category) |
|---|---|---|
| Ticket database and fields | Not documented in sources reviewed | Core feature |
| Inbound channels | Many platforms via the gateway ([messaging](https://hermes-agent.nousresearch.com/docs/user-guide/messaging)) | Varies by tool |
| FAQ answering | Skill-based pattern ([skills](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills)) | Usually built-in knowledge base |
| Scheduled digests | Cron tool ([cron](https://hermes-agent.nousresearch.com/docs/user-guide/features/cron)) | Usually built-in reporting |
| External event triggers | Webhook routes ([webhooks](https://hermes-agent.nousresearch.com/docs/user-guide/messaging/webhooks)) | Usually integrations |
| Human handoff | DIY: alert to a human target ([cron](https://hermes-agent.nousresearch.com/docs/user-guide/features/cron)) | Usually built-in assignment |
| Queues, SLA, assignment | Not documented in sources reviewed | Core feature |
| License | MIT ([repository](https://github.com/NousResearch/hermes-agent)) | Varies (commercial subscriptions are typical) |

The dedicated-tool column reflects general product categories, not verified claims about specific products.
